Beyond Heuristics. Toward Verified Decompilation.

Bringing Formal Verification to Reverse Engineering.

DeCompCert is a formally verified decompilation framework that reconstructs high-level C programs from assembly. It combines automated program reconstruction, machine-checked proofs, and translation validation to establish semantic guarantees for accepted reconstructions.

Why DeCompCert

Decompilation is inference.Correctness should not be.

Compilation erases names, types, stack abstractions, register boundaries, and structured control flow. Conventional decompilers use powerful heuristics to recover plausible source. DeCompCert keeps that flexibility, then checks the result.

Formal assurance

Two proof styles.A single semantic story.

3

DIRECTLY VERIFIED PASSES

Reconstruction and proof live together in Rocq.

A state relation connects the higher- and lower-level executions. Initial states, execution steps, and final states are proved to correspond.

6

TRANSLATION-VALIDATED PASSES

Untrusted generators. Proved acceptance checks.

A generator may search aggressively. A proved validator accepts only candidates connected to the lower-level input by the required semantic result.

✓
COMPOSED THEOREMAccepted C → supplied Asm
Every accepted result Decompile(PAsm) = OK(PC) ⇒ Behaviors(PC) ⊑ Behaviors(PAsm)
When reconstructed C is safe Decompile(PAsm) = OK(PC) ∧ Safe(PC) ⇒ Behaviors(PC) = Behaviors(PAsm)

The first result is unconditional for every accepted reconstruction. The second rules out undefined C executions and strengthens the result to equality of observable behaviors.

What is inside the trusted boundary?

The theorem begins at typed, unexpanded CompCert Asm. Parsing assembly text, reversing concrete instruction expansion, and constructing that typed representation precede the theorem. Experimental Clang normalization is likewise outside the current mechanized guarantee.
